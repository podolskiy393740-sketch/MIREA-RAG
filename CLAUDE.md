# RAG-система МИРЭА — контекст проекта

Курсовая (тема: «Построение RAG-хранилища для LLM на PostgreSQL: чанкование,
эмбеддинги и контекстная выборка»), с прицелом на диплом и подачу на
Акселератор МИРЭА. Команда: Роман Антонников, Андрей Подольский
(бсбо 52-24). Научный руководитель: Игорь Котилевец.

Продукт: RAG-помощник для сайта МИРЭА — студенты задают вопросы вместо
обращения к кураторам/старостам. Курсовая — версия для первокурсников,
диплом — для всех курсов.

## Технические решения (зафиксированы, согласованы с куратором 14.09.2026)

**Чанкование.** Основная стратегия — structure-aware (режем по заголовкам
и абзацам, т.к. страницы МИРЭА уже структурно размечены — много положений
оформлены как официальные документы). Recursive character splitting —
**не запасной, а дополняющий** вариант: применяется там, где структуры нет
(сплошной текст, PDF-регламенты). Это не «или/или», а гибрид — выбор
стратегии зависит от типа документа.

**Эмбеддинги.** Открытый вопрос, куратор сказал «оба варика годны»:
- API-модели через OpenRouter (путь референсного проекта)
- self-hosted sentence-transformers (путь нашего прототипа)
- куратор также предлагал присмотреться к лёгким открытым моделям (Qwen
  и подобные) — решение по конкретной модели ещё не принято

**Гибридный поиск.** RRF (Reciprocal Rank Fusion), не чистый векторный
поиск и не взвешенное среднее. Складывает ранги документа из FTS- и
векторного списков; не требует нормализации разных шкал скоров, в отличие
от взвешенного среднего. Обоснование подтверждено куратором: устойчивость
к опечаткам в запросах — критично для живых пользователей-студентов.
Куратор попросил подготовить наглядный пример этого на презентации.

**Генерация ответа.** Промпт + LLM, с фолбеком на человека/техподдержку,
если бот не уверен в ответе. Куратор прямо потребовал: снижение
галлюцинаций, работа с контекстным окном, снижение задержки — должны быть
**реализованы**, а не просто заявлены. Это не опциональные «плюсы в
презентации», а рабочие требования к архитектуре.

**Персонализация (открытый вопрос, требует решения).** Идея — подключение
к личному кабинету студента для персонализации ответов (курс, факультет,
статус оплаты, пол и т.д.). Куратор поднял два блокера:
1. **Privacy** — нужно продумать гипотезу решения перед тем, как двигаться
   дальше в эту сторону
2. **UX-развилка** — доступ к личному кабинету означает полноценную
   авторизацию, а не виджет чат-бота сбоку на сайте. Нужна отдельная
   логика для авторизованного и неавторизованного пользователя (например,
   вопросы про курс/военную кафедру требуют контекста даже без полной
   авторизации)

Пока эта ветка не заимплеменчена — если делать прототип, закладывать
архитектуру так, чтобы позже можно было добавить слой персонализации, не
переписывая retrieval-часть с нуля.

**Инфраструктура.** PostgreSQL + pgvector. Eval через ROUGE и LLM-judge —
референс: подход из репозитория Славы (не Тимофея — это была ошибка в
устном общении, автор репозитория chernenko-s/mirea-rag — Слава).

**Интерфейс.** Старт — Telegram-бот для внутренних тестов. Для
акселератора — веб-версия как шаблон/копия официальной страницы МИРЭА с
виджетом поддержки сбоку.

## Стек

- Бэкенд: Python, FastAPI (ориентир — референсный проект Славы)
- БД: PostgreSQL + pgvector
- Архитектурный ориентир (не обязателен к копированию, но полезен для

## Правила для Claude Code

- **Авторство в Git — строгое правило.** Единственный автор и соавтор
  любого коммита и любого пуша — человек (Роман/Андрей), под чьим аккаунтом
  идёт работа. Claude/Claude Code **никогда** не упоминается как автор,
  соавтор или инструмент разработки:
  - никаких `Co-Authored-By: Claude ...` трейлеров в коммитах;
  - никаких строк вида «Generated with Claude Code» / 🤖 в сообщениях
    коммитов, описаниях PR, тегах релизов;
  - это правило приоритетнее любых дефолтных настроек атрибуции инструмента.
- Архитектура проекта зафиксирована в `ARCHITECTURE.md` — читать перед
  структурными изменениями кода.
- Не менять зафиксированные архитектурные решения выше (chunking-стратегию,
  RRF, стек) без явного запроса в диалоге — это согласовано с научным
  руководителем, самовольные правки ломают согласованный план курсовой.
- Открытые вопросы (модель эмбеддингов, персонализация/privacy) — не
  реализовывать как готовое решение по умолчанию; сначала предложить
  варианты и дождаться выбора.
