# Сбор реальных данных с сайта МИРЭА

## Проблема: mirea.ru недоступен с машин разработки

`mirea.ru` закрыт защитой DDoS-Guard по гео-блокировке — прямые запросы
(`curl`, встроенный WebFetch) получают отказ (403 / geoblocked), не заходя
дальше сетевого уровня. Это подтверждено и не зависит от кода — сайт
физически не отвечает на запросы с этой инфраструктуры.

## Рассмотренный и отклонённый вариант: CSV Славы

У референсного проекта `chernenko-s/mirea-rag` есть готовый набор
`data/qa_pairs.csv` (196 пар вопрос-ответ, извлечённых из официальных
документов МИРЭА). Мы **не стали его использовать**: у репозитория нет
файла LICENSE, а датасет похож на проделанную вручную работу автора
(`is_generated=TRUE`), а не на открытые данные — команда решила не
использовать его без явного разрешения автора/куратора. Код под этот
формат CSV подготовлен на будущее (`src/infrastructure/ingestion/qa_csv_source.py`),
но сами данные Славы в репозиторий не добавлялись и не скачивались.

## Решение: Wayback Machine

Вместо прямого обращения к `mirea.ru` страницы получены через
**web.archive.org** (Wayback Machine, Internet Archive) — публичный архив
интернета, хранящий кэшированные копии публично опубликованных страниц.
Технически это не обход блокировки mirea.ru: запросы идут только к
серверам archive.org, к самому mirea.ru обращений нет вообще.

Механика (`src/infrastructure/ingestion/wayback_fetcher.py`):
1. CDX API archive.org возвращает список снапшотов данного URL — берём
   самый свежий доступный (HTTP 200).
2. Снапшот скачивается через `.../web/<timestamp>id_/<url>` — суффикс
   `id_` отдаёт архивную копию как есть, без тулбара Wayback Machine.
3. Ретраи с бэкоффом на обоих шагах: архив периодически отдаёт
   503/HTML-страницу "Temporarily Offline" вместо ожидаемого ответа — это
   временная перегрузка самого архива, наблюдалась многократно при сборе
   этих данных, не признак проблемы с URL.

Скрипт `scripts/fetch_real_pages.py` — курируемый список страниц,
идемпотентный (манифест мержится, а не перезаписывается: если архив не
отдал часть страниц в очередной прогон, ранее скачанные не теряются).

## Находка и фикс: мега-меню в тексте

Первая версия `html_to_markdown` конвертировала весь `<body>` целиком.
На реальных страницах mirea.ru это означало: конвертированный текст на
~95% состоял из мега-меню сайта (сотни пунктов навигации, повторяющихся
на каждой странице) и лишь на ~5% — из содержания статьи. Разбор HTML
показал, что шаблон сайта кладёт заголовок и текст статьи в предсказуемые
контейнеры (`h1.page-title` + `div.app-content`), отдельно от меню —
`html_to_markdown` исправлен, чтобы вычленять именно их. Пример: страница
про общежития — 545 КБ исходного HTML → раньше 274 КБ markdown (почти
весь — меню) → после фикса 10 КБ markdown (только реальный текст, с
корректными заголовками `## Общежитие №1`…`№6`).

Fallback: если известных классов нет (например, у страниц в архивных
снапшотах шаблона 2015–2020 годов), парсер отдаёт всё тело как раньше —
не идеально, но не падает.

## Собранные страницы (первый набор)

Отобраны под фокус курсовой (версия для первокурсников, см. `CLAUDE.md`).
Хранятся в `data/raw_html/`, происхождение каждой — в `data/raw_html/manifest.json`
(source_url, timestamp снапшота, прямая ссылка на архивную копию).

| Страница | source_url |
|---|---|
| Общежития | `/about/infrastructure/obshchezhitiya/` |
| Столовые, буфеты | `/about/infrastructure/stolovye-bufety/` |
| О начале учебного года для первокурсников | `/ads/o-nachale-uchebnogo-goda-dlya-pervokursnikov-rtu-mirea/` |

## Не доделано (не блокер)

- **Спортивная инфраструктура** — не удалось скачать: архив был
  перегружен во время сбора. Страница в курируемом списке
  (`scripts/fetch_real_pages.py`), можно дособрать позже повторным
  запуском скрипта.
- **Военная кафедра** — существует в архиве только в шаблоне сайта
  2015–2020 годов (без `app-content`/`page-title`), парсер её пока не
  извлекает избирательно, падает на fallback (весь body). Нужно либо
  добавить эвристику под старый шаблон, либо найти актуальный URL.

## Как дособрать ещё страниц

```
python -m scripts.fetch_real_pages --out data/raw_html
```

Добавить новую страницу — просто дописать пару `name: url` в
`TARGET_PAGES` в `scripts/fetch_real_pages.py`.
