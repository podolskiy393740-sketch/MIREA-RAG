# Результаты eval

Методология — `CLAUDE.md` ("Eval через ROUGE и LLM-judge") и код в
`src/infrastructure/eval/`. Запуск: `python -m scripts.run_eval`.

## Прогон 2026-09-18

- **Датасет:** `data/external/mirea_rag_slava_test.csv` — held-out набор
  Славы, 49 вопросов, отдельный от того, что проиндексировано в базе.
- **База на момент прогона:** 25 документов, 60 чанков (CSV Славы про
  поступление/общежития/оплату + 4 страницы через Wayback Machine).
- **Эмбеддинги:** Qwen3-Embedding-0.6B, self-hosted.
- **Генерация и judge:** OpenAI `gpt-5.4-nano`.

```
cases_total=49
cases_scored=49
cases_errored=0
human_fallback_rate=16.3%
success_rate_ge_4=79.6%
judge_score: mean=4.06 p10=1.00 p50=5.00 p90=5.00
rouge_1_mean=0.57
rouge_l_mean=0.54
latency_ms: mean=2288.94 p10=1468.02 p50=1752.62 p90=2410.75
```

**Интерпретация:**
- **Задержка** — среднее 2.3 с, p90 2.4 с: стабильно и предсказуемо
  (в отличие от бесплатного тира OpenRouter в тот же день — там среднее
  было 7-17 с из-за перегрузки/ретраев, см. `project memory`). Прямое
  подтверждение требования куратора по снижению задержки.
- **Бимодальность judge_score** (p10=1, p50=5, p90=5) — ожидаемо: судья
  ставит 1, когда бот честно ответил "недостаточно данных" вместо ответа
  по существу (16.3% таких случаев), и 4-5, когда данные в базе были.
  Это не ошибка модели генерации, а прямое следствие текущего объёма
  проиндексированных данных — 25 документов не покрывают все 49
  эталонных вопросов Славы (ожидаемо, у нас другой источник данных).
- **rouge_1_mean=0.57** — на кейсах, где база реально что-то знает,
  сформулировано похоже на эталон, но не дословно (ожидаемо для LLM
  вместо генерации по шаблону).

**Ближайший рычаг улучшения — не модель, а объём данных:** чем больше
реальных страниц/документов проиндексировано, тем ниже
`human_fallback_rate` и выше средний `judge_score`.

## Как посмотреть на конкретные провалившиеся кейсы

```
python -m scripts.run_eval --output eval_run.json
```

Сохранит полные результаты (вопрос, эталон, ответ модели, все метрики)
по каждому кейсу — удобно для разбора, какие именно вопросы ушли в
фолбек, без повторного дорогого прогона.
